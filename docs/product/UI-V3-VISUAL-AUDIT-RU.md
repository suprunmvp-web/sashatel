# SashaTel UI v3 — визуальный аудит и критерии приёмки

Статус: дизайн-ревизия в PR #43. Не равнозначна API-интеграции или разрешению merge.

## База сравнения
Resend Dashboard: одна понятная вертикальная навигация, ограниченный контентный холст, простые таблицы с ровным ритмом, точечные статусы, минимальное число поверхностей. Linear: удобный переключатель контекста и лаконичные состояния. Авторизация SashaTel и утверждённая продуктовая архитектура остаются исходными функциональными ограничениями.

## Системные недостатки предыдущей версии
1. **Неудачная композиция:** сайдбар показывал бренд вместо контекста организации, а организация дублировалась в правой части шапки. Исправлено: organization switcher слева сверху, профиль и тема справа.
2. **Инструменты ревью на виду у клиента:** огромные кнопки «С данными» и «Тёмная тема» выглядели как функции продукта. Исправлено: демонстрационные данные выведены в отдельный инспектор, тема — только иконкой.
3. **Бесконтрольная ширина:** на 1440 px таблицы растягивались почти на 1120 px при малом числе строк. Исправлено: единый ограниченный центральный контейнер.
4. **Неровные отступы:** верхний breadcrumb, заголовки, подзаголовки, вкладки и таблицы жили на разных вертикальных ритмах. Исправлено: 62 px header, 25 px после заголовка, унифицированные интервалы.
5. **Избыточное дублирование:** «Транки» + «SIP-ТРАНК» + название конкретного транка одновременно. Исправлено: на detail-экране основной заголовок списка скрыт; остаются ссылка назад и контекстный заголовок.
6. **Пустота как баг:** таблица на весь экран и 2 строки в углу; повторные заглушки и технические предупреждения. Исправлено: ограниченная ширина, компактная таблица, единственное осмысленное zero state.
7. **Слабые состояния данных:** встречались фиктивные нули там, где статус не известен. Исправлено: «—» для недоступной информации, ноль только при известном количестве.
8. **Слишком много декоративных линий:** границы использовались без смысловой группировки. Исправлено: внутри таблицы — строки, вокруг статистического блока — один контейнер.
9. **Тяжёлый график:** занимал слишком много места, подписи и значения не связывались. Исправлено: одна линия дозвона; подробные минуты, инициации и ответы в tooltip.
10. **Неоднородные табы:** active/passive номера и детали вызова выглядели как разные продукты. Исправлено: общие сегменты, единые табы и единый стиль таблиц.
11. **Некачественная мобильная версия:** прежняя компоновка с длинными элементами управления создавала горизонтальное переполнение. Визуальный CI проверяет четыре ширины, детали требуют регрессионного прогона.
12. **Нет единого визуального языка админки:** клиентский и внутренний режимы различались только названиями. Исправлено в shell; внутренние конкретные модули требуют дальнейшего продуктового и RBAC проектирования.

## Экранная приёмка — вопросы перед merge
- **Статистика:** сверху сразу видно дозвон и четыре KPI? Tooltip не перекрывает данные? Кольцо и легенда воспринимаются одним блоком? Нет фиктивной активности?
- **Транки:** основной CTA расположен рядом с контекстом? Регистрация, готовность и состояние различимы? Таблица не выглядит растянутой? Для пустого списка одно понятное действие?
- **Транк / номера:** есть ясный возврат, один заголовок, вкладки сразу под ним, фильтр рядом с таблицей и понятные состояния номеров? Нет отдельного пустого «этажа» между ними?
- **История:** запись открывается из строки; время, сотрудник и результат сканируются взглядом?
- **Карточка звонка:** основные факты вверху, саммари и транскрипт/детали разнесены по смыслу?
- **Сотрудники:** роли и присутствие читаются, приглашение заметно без навязчивости?
- **Интеграции:** карточки объясняют доступные подключения, а не имитируют готовую интеграцию?
- **Биллинг:** значения не придумываются, документы читаемы, действие оплаты не обещано при отсутствии API?
- **Админка:** выбор контекста не дублируется, internal доступ не выводится для клиента и не открывается без серверной проверки?

## Границы
- В review-сборке допускаются явно помеченные искусственные данные только для оценки заполненных экранов; в production они запрещены.
- Внешний Resend — стилистический и UX-ориентир, не источник авторизации или функционального контракта SashaTel.
- Backend, RBAC, API данных и настоящие действия не менялись этой веткой.
