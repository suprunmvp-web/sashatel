# Backend ↔ UIS worker v1 | предложение на согласование в #14

Backend аутентифицирует организацию администратора Web SaaS, авторизует trunks.manage, публикует durable job и остаётся единственным владельцем разрешения на внешний вызов. Worker привязан конфигурацией к одной паре tenant_id/trunk_id на узел. Другие пары отклоняются до доступа к Asterisk. Эти настройки нельзя принимать из пользовательского запроса. Изоляция нескольких одновременно загруженных trunk на одном узле требует отдельной реализации.

Запрос на очереди: schema_version=1, request_id, tenant_id, trunk_id, expected_revision (null только при первом заказе), revision, enabled, profile_ref, secret_ref. ID и revision — канонические UUID. Ссылки принадлежат тому же tenant и trunk. Доверенный adapter держит credentials в vault, проверяет scope обеих ссылок и передаёт приватные файлы вместе с локальным JSON из шести полей request_id/tenant_id/trunk_id/expected_revision/revision/enabled. Для отключения файлы не передаются. Один ID привязан к неизменяемому запросу, профилю и версии секрета. Worker не читает очередь или vault напрямую.

Receipt синхронного apply: request_id/status. Событие adapter: schema_version, request_id, tenant_id, trunk_id, revision, active_revision, status, observed_at, reason_code. Status: applied (конфиг загружен), registered (PJSIP зарегистрирован при наблюдении), disabled, rolled_back. Неуспешный CLI возвращает ненулевой код и redacted сообщение. Adapter публикует failed_closed при неопределённом исходе и повторно сверяет status под авторизованным управлением. Машиночитаемые ошибки очереди: invalid_request, scope_mismatch, revision_conflict, runtime_unverified. Первые три формирует adapter из валидатора и проверенного контекста. CLI намеренно не разделяет ошибки и не выдаёт сырой вывод Asterisk. registered не означает usable.

Перед apply adapter закрывает dispatch, дожидается завершения in-flight и fencing новых попыток. При reboot, потере связи или неопределённой операции держит dispatch закрытым до нового наблюдения. Команда status может выполнить восстановление незавершённой транзакции: запускать только у доверенного локального worker, а не из пользовательского GET. Отключённая ревизия сохраняет fencing поколения. Для вызова нужен отдельный ARI adapter, проверка точного разрешённого ID и destination и reconciliation всех legs. Локальная проверка ARI Local pair в CI не означает подтверждённую работу UIS-leg или внешнего маршрута.
